# contracts

Language-neutral data contracts shared by every HaryX part (macOS app, `haryx` CLI, and later server, web, iOS,
Android). Add or change a shape here first, then update the code that reads or writes it.

| Path | What | Checked by |
|---|---|---|
| `haryx/upgrade-check.json` | `haryx upgrade --check --json`: the latest release, its notes and this machine's app and CLI downloads | `cli/crates/haryx/src/commands/upgrade.rs`, both apps' tests |
| `haryx/whoami.json` | `haryx whoami --json` and `haryx logout --json`: whether this machine is signed in to a HaryX account. Signed out is `{"signedIn": false, "user": null}`. `provider` is `github`, `google`, `apple` or `email` (WeCoAp SSO; a token with no `identity_provider` claim is `email`). `consents` (top level, absent when signed out) is the user's HaryX consents: `purpose`, `granted`, `version` (null when never answered). Never carries a token. Breaking change: none; `consents` and the two new providers are additions, and consumers must tolerate unknown providers. | `cli/crates/haryx/tests/account.rs` |
| `haryx/login-events.json` | `haryx login --json`: one JSON object per line, in this order. `browser` (the sign-in URL; `opened` is false with `--no-browser` or when no browser could start), then `signed_in` or `error`. Error `code`: `timeout`, `denied`, `refused`, `network`, `storage`. | `cli/crates/haryx/tests/account.rs` |
| `haryx/sync-result.json` | `haryx sync --json`. On failure `{"ok": false, "code": …, "message": …}` with exit 1; `code` is `not_signed_in`, `locked`, `wrong_passphrase`, `key_changed`, `busy`, `invalid`, `local`, `server`, or a sign-in code (`network`, `signed_out`, …). `changed` lists kinds that changed this machine: `settings`, `app-prefs`, `account`, `credential`. `lost` is null when the losing side had the value unset, and always null for tokens. | `cli/crates/haryx/tests/sync.rs` |
| `haryx/sync-status.json` | `haryx sync status --json`: local only, no network. `lastSyncAt` is null before the first sync. | `cli/crates/haryx/tests/sync.rs` |
| `haryx/consents.json` | `haryx account consents --json`, and the body of `GET /api/v1/consents`: one shape for both, camelCase. One entry per `purpose` (`sync`, `machines`): `granted`, and `version` (policy version) and `at` (ISO UTC) of the latest event, both null when never answered; `history` is every event, oldest first: `action` (`grant`, `withdraw`), `version`, `at`, `source` (`cli`, `macos`, `windows`, `web`, `sso`). Withdrawn data is gone, the events stay. | `cli/crates/haryx-core/src/contracts.rs`, both apps' tests |
| `haryx/machines.json` | `haryx account machines --json`, and the body of `GET /api/v1/machines`: `machineId` (UUID), `name`, `os` (`macos`, `windows`, `linux`), `version`, `lastSeenAt` (ISO UTC), `isThisMachine` (the API sets it for the row whose session is the caller's token `sid`; the CLI also matches its local machine id), `signedIn` (the machine's session is not revoked), `sessionId` (the machine's Keycloak session; the web names it to Keycloak's account API to end that session, A7). Needs the `machines` consent; without it the list is empty. | `cli/crates/haryx-core/src/contracts.rs`, both apps' tests |
| `haryx/usage-sync.json` | The plaintext body of one `usage` sync row, before encryption: one per (machine, month), key `row_key("usage:<machineId>:<month>")`. `days` has one row per (`day`, `account`, `model`) with token counts (no cost: prices are applied when shown); `account` is the Claude account's email, null when unattributed. `quota` holds 5h/7d readings (`at` epoch seconds, percents null when absent). It never carries a project path, a file name, a session id or conversation text. | `cli/crates/haryx-core/src/contracts.rs`, both apps' tests |
| `haryx/app-prefs.json` | `haryx sync prefs get` / `set` (stdin): the apps' synced preferences, one flat object. Shared keys have no prefix; `macos.*` and `windows.*` are read only by that app. The CLI stores and merges it per key without interpreting it. Never put a path or a secret here. Notifications use the apps' category names (`notifications.switched`, `usage`, `login`, `reset`, `session`, `autoSwitch`); `mascotStyles` maps `email|organizationUuid` to `{species, hue}` (hue optional), species one of the eight shared sprites. | the apps |
| `haryx/sync-profiles.json` | `haryx sync profile list --json`: setup profiles kept on the server (3 at most). | `cli/crates/haryx/tests/sync.rs` |
| `cswap/list.json` | `cswap list --json` / `haryx list --json` payload (schemaVersion 1, from cswap 1.1.0, anonymised) | `apps/macos/Tests/HaryXCoreTests` |

The Ruby CLI must produce output that matches these fixtures (drop-in compatibility with cswap).

The web platform (`apps/platform`, task 16 of `docs/sso-platform-plan.md`) does not exist yet; it will read the
same `consents`, `machines` and `usage-sync` shapes, and gets its decode tests then.
